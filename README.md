# primeodin — Rune-King in the Machine

I build small machines for large questions.

This profile is an honest retrospective archive: a mythic technical autobiography, not a forged public record. I keep the story dressed in frost and iron because that is how my mind remembers hard work: winters of debugging, chalkboards full of guesses, and the private joy Feynman named so well — the pleasure of finding things out.

The path here runs from low-level C and hand-rolled parsers through physics toys, utility AI, neural nets, parallel loops, cloud survival, reinforcement learning, quantum circuits, resilient systems, attention, and prompting. Each repository is a chapter. Each chapter asks the same old question in a new dialect: what invariant must hold when the storm arrives?

A rune is just an invariant with poetry on it. Rage is just energy under governance. A kingdom is a system with people depending on it.

I do not claim these repositories lived publicly in their chapter years. They were forged later as reconstructions: period-aware code, narrative notes, and small runnable examples designed to make the arc visible without inventing false footprints. Legends are not weakened by honesty. They are tempered by it.

If you are here to learn, begin anywhere. Run the code. Break it. Repair it. Write down what changed. The machine is a better teacher than a slogan, and a small example that fails clearly is worth more than a cathedral nobody can enter.

Still hungry for the next winter.
